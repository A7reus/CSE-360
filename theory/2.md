# Lab 2 Theory - Packet Tracer Basics, Client Server, DNS and HTTP

Source: `slides/2.pdf`. This file explains the ideas behind what you click in the simulator. If you understand this, the clicks start to make sense.

## 1. What Packet Tracer is

Packet Tracer is a simulator for Cisco devices. In real life you would need real routers, switches, PCs and cables. In the simulator you drag the same devices onto a canvas and connect them with virtual cables. The devices behave like simplified versions of the real ones. This is mainly used for CCNA and CCNP practice.

Two dot colors matter a lot. Red means the link is down. Green means the link is up. If you just connected something and it is red, wait a bit or check power and configuration. A lot of beginner problems are just red links.

## 2. Hub, switch and wireless: the same subnet idea

### 2.1 IP address, subnet mask and netid

Every PC in these early examples has an address like `192.168.0.1` with mask `255.255.255.0`.

Think of it in two parts. The mask tells which part is the network and which part is the host. With `255.255.255.0`, the first three numbers are the network part. All PCs with `192.168.0.x` are in the same network. That shared part is sometimes called netid or network address, here `192.168.0.0`. The last number is the host part and must be unique. You cannot give two PCs the same full address.

If all machines share the same netid, they can talk directly without a router. That is called a subnet in these slides.

### 2.2 Hub

A hub is the simplest box. It works like a repeater. Whatever comes in on one port is copied out of all other ports in all directions. Every PC receives the signal, but only the PC whose address matches accepts it. The rest ignore it.

Consequence: only one conversation can succeed at a time on a hub. If two PCs send together, the signals collide. In the simulator you verify a hub network with `ping`. If ping works, basic connectivity is fine.

### 2.3 Switch

A switch looks similar but is smarter. It learns which MAC address lives on which port. A MAC address is the hardware address burned into each network card. After learning, the switch forwards a packet only to the correct receiver port, not everywhere.

In Packet Tracer you have to wait a little after connecting to a switch. The port goes through checks before it turns green. Students often think the network is broken when it just needs 30 to 60 seconds. Wait for green, then ping.

### 2.4 Wireless

The wireless example is logically the same subnet idea, just without cables. PCs connect to an access point instead of a hub or switch. You still give them IP addresses in the same network and test with `ping` and with simulation mode.

## 3. How to talk to a switch or router for configuration

There are two ways: directly with a console cable, or remotely over the network.

### 3.1 Console cable

You connect a PC serial port to the device console port with a light blue console cable. Then on the PC you open Terminal or Command Prompt and you get the device prompt like `Switch>`.

The prompt has levels:

* `Switch>` is user mode. You can look but not change much.
* `Switch#` is privileged mode. You get there with `en` or `enable`.
* `Switch(config)#` is global configuration mode. You get there with `conf t`. From there you change settings.
* `Switch(config-line)#` is line configuration for console or telnet lines.

In the slides you set two passwords:

```
Switch>en
Switch#conf t
Switch(config)#enable secret ju123
Switch(config)#line console 0
Switch(config-line)#password cseju
Switch(config-line)#login
Switch(config-line)#end
Switch#copy run startup-config
```

What this means in plain words:

* `enable secret ju123` sets the password to go from `>` to `#` to `ju123`. Secret means it is stored in encrypted form.
* `line console 0` selects the physical console port.
* `password cseju` plus `login` means anyone opening the console must type `cseju` first.
* `copy run startup-config` saves. The router or switch has running memory and startup memory. If you do not save, your work is lost after a reboot. `wr` is the short form of the same save.

Next time you connect, it asks `Password:`, you type `cseju`, then `en`, then it asks `Password:` again and you type `ju123`.

In real life you would use HyperTerminal or a similar program with a real serial cable. In Packet Tracer you just click the PC, go to Desktop, open Terminal, and accept defaults.

### 3.2 Telnet and remote access

Once a device has an IP address, you can reach it without walking to it. Telnet is the old simple way:

```
Switch(config)#line vty 0 4
Switch(config-line)#password imdad
```

`vty 0 4` means 5 virtual terminal lines, numbered 0 to 4. So 5 people can telnet in at the same time. The password here is `imdad`.

SSH with tools like PuTTY or SSH Secure Shell Client is the same idea but encrypted. You put the device IP address, click Open, and you get the same prompt. Telnet sends passwords in clear text. SSH encrypts them. That is the main difference you need to remember at this stage.

## 4. Basic client server model (Expt-1)

Goal: one PC called client talks to one server. The server will do two jobs at once: DNS server and web server. Then you test with browser and with command line tools.

### 4.1 Wiring

One PC-PT and one Server-PT connected with a copper straight through cable. Green dots mean the physical link is up.

### 4.2 IP configuration

Click client, go to FastEthernet or IP Configuration:

* IP address of client, for example `192.168.0.1`
* Subnet mask `255.255.255.0`
* DNS Server field: the IP of the server, for example `192.168.0.105`

Click server, Config, FastEthernet:

* IP address of server, for example `192.168.0.105`
* Same mask

Why does the client need the DNS Server field. Because when you later type a name like `www.kuddus.com`, the PC does not know the number. It must ask a DNS server. If that field is empty or wrong, names fail even when ping by number works. This is the most common mistake.

### 4.3 DNS record

Click server, Config, DNS. Turn DNS Service On. Then add:

* Name: `www.kuddus.com`
* Address: `192.168.0.105`
* Type: A Record
* Click Add, then Save

An A Record is simply a mapping from a name to an IPv4 address. DNS Service must be On. If it is Off, the records sit there but the server never answers. We saw exactly this bug in `pkt/2-2.pkt` where records existed but `ENABLED=0`, so browsing by name failed.

### 4.4 Test with simulation and browser

Simulation mode lets you watch the ICMP packet go from client to server and back. That proves Layer 3 works.

Then Desktop, Web Browser, type `http://www.kuddus.com` and click Go. Steps behind the scenes:

1. PC sees the name is not an IP, so it sends a DNS query to `192.168.0.105`.
2. Server replies `192.168.0.105`.
3. PC opens an HTTP connection to that IP and asks for the page.
4. Server returns the HTML stored under Services, HTTP.

If the browser says host not found, it is a DNS problem. If it times out, it is connectivity. If it says 404, HTTP file name is wrong.

### 4.5 Command line checks

On client Command Prompt:

* `ping 192.168.0.105` tests reachability by number. Reply with `bytes=32 time=... TTL=128` means success.
* `ping www.kuddus.com` tests DNS plus reachability. If the first works but this fails, DNS is the culprit.
* `tracert www.kuddus.com` shows each hop. In a single cable network it is one hop.
* `ipconfig` shows your own IP, mask, gateway.
* `arp -a` shows the ARP table, which maps IP addresses to MAC addresses learned on the LAN. ARP is how a PC finds the hardware address to actually send the frame.

## 5. DNS server configuration with a router (JU and DU networks)

This is `pkt/2-2.pkt`. Two separate LANs joined by one router.

### 5.1 Topology in plain words

Left side is JU:

* PC `192.168.1.1`, mask `255.255.255.0`, gateway `192.168.1.4`, DNS `192.168.1.3`
* PC `192.168.1.2`, same gateway and DNS
* Server `192.168.1.3`, gateway `192.168.1.4`, DNS itself `192.168.1.3`
* Router Fa0/0 `192.168.1.4`

Right side is DU:

* PC `192.168.2.1`, gateway `192.168.2.4`, DNS `192.168.2.3`
* PC `192.168.2.2`, same
* Server `192.168.2.3`, gateway `192.168.2.4`, DNS itself
* Router Fa0/1 `192.168.2.4`

All devices on one side go through a 2950 switch. The switch needs no IP for this lab. It just forwards.

### 5.2 Why gateway and why router ports must be On

A PC only knows its own subnet. To reach the other university network, it sends to its gateway, which is the router leg in its own subnet. If gateway is wrong, local ping still works but remote fails.

On the router, click Config, select Fa0/0, set IP `192.168.1.4`, mask `255.255.255.0`, check Port Status On. Same for Fa0/1 with `192.168.2.4`. If Port Status is Off, it is like the cable is unplugged. In CLI that is `shutdown` versus `no shutdown`.

### 5.3 DNS on both servers

Per slides, put both records on both servers:

* `www.ju.edu` to `192.168.1.3`
* `www.du.edu` to `192.168.2.3`

Why both. In this simple lab there is no DNS hierarchy or forwarding. Each PC only asks its local server. If a DU PC wants `www.ju.edu` but its server only knows `www.du.edu`, it gets no answer. So you duplicate the two A Records on both sides. And again, DNS Service must be On on both.

### 5.4 HTTP files

Click server, Services, HTTP. Make sure HTTP and HTTPS are On. The file list has `index.html` by default. You add `ju.html` on the JU server with the Jahangirnagar HTML from the slides, and `du.html` on the DU server with the Dhaka HTML. The file name matters exactly, lower case. Browsing `http://www.ju.edu/ju.html` means: resolve `www.ju.edu`, connect, ask for file `ju.html`. If you type the IP directly like `http://192.168.1.3/ju.html`, you skip DNS. That trick tells you whether the problem is DNS or HTTP.

### 5.5 How to debug browsing failures

Use this order:

1. `ping` the server IP. Fail means cable, IP, mask or switch.
2. `ping` the name. If IP works but name fails, check PC DNS field, server DNS On, and A Record spelling. Do not put `/ju.html` inside the DNS Name field. DNS only maps the host part.
3. Browse by IP. If name fails but IP works, it confirms DNS. If IP also fails, check HTTP On and that `ju.html` exists and was saved.
